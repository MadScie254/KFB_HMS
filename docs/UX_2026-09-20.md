# Interface work — 20 September 2026

Six layout and legibility defects, found by looking at the running screens
rather than the code, plus four additions. Every item was verified in a real
browser at 1440×900 and 390×844; the interaction layer has its own scripted
check that exercises each behaviour.

---

## The defects

### 1. On a phone, the two columns that matter were off-screen

The patient queue rendered as a wide table inside a horizontally scrolling box.
On a 390px screen that put **Status** and **Waiting** past the right edge,
behind a sideways swipe with no affordance announcing it. The product exists so
an owner can check the hospital from their phone, and on a phone they could not
see how long anybody had been waiting.

**Fixed** by stacking every table into labelled cards below 720px. Each cell
takes its label from its column header — done in JavaScript, so no template
had to be rewritten and a table added later gets the treatment automatically.
Nothing is clipped, and a scripted check asserts that every stacked cell carries
a label.

### 2. A twelve-hour wait looked exactly like a five-minute one

Nothing on the queue escalated. **Fixed** with three bands — under an hour, over
an hour, over three hours — shown as colour, a row tint, and **words**
("Waiting a long time"), because colour alone is not a message to someone who
cannot see it. The queue page also had no waiting column at all; it does now,
and it sorts.

### 3. The dashboard stranded a KPI card alone

Six cards in a fixed five-column grid left the sixth by itself with four empty
columns beside it. `auto-fit` does not fix this — it picks a column count from
the width and strands the same card.

**Fixed** with a quantity query: the grid counts its own children and chooses a
track count that divides evenly, so six become two rows of three and eight
become two rows of four.

### 4. Two-thirds of the lower dashboard was empty

The Exceptions panel occupied one of three columns with nothing beside it.
**Fixed** by giving it the full row, with its list flowing into columns so a
wide panel is not a sparse one.

Worth recording: `grid-column: 1 / -1` **does not span the row** when the grid
uses `repeat(auto-fit, …)`, because the collapsed empty tracks change what `-1`
means. The grid now declares explicit tracks at each breakpoint.

### 5. The phone topbar lost who you were

Name and role were hidden below 900px, leaving a green dot. On a shared ward
device nobody could tell which account was signed in. **Fixed**: the identity
stays, truncated rather than dropped.

### 6. Figures were unreadable at a glance

`KES 1540200.00`. One setting — `USE_THOUSAND_SEPARATOR` — makes every rendered
number grouped, across every template at once: `KES 1,540,200.00`.

That created a second problem worth fixing in the same breath: a figure copied
off the screen and pasted into a form came back as "Enter a number", because
form parsing stayed unlocalised. Numeric fields now strip the separators they
were displayed with. Rejecting somebody's own number back at them is a dead end.

## The additions

### Search from anywhere

`/` or `Ctrl`/`Cmd`+`K` opens a palette that searches patients, visits, batches,
pharmacy orders and deliveries at once. Arrow keys move, Enter opens the first
hit without pressing Down first.

**It is scoped by role, and that is tested.** A receptionist who cannot open the
stock ledger cannot read batch numbers out of the search box either; the pharmacy
cannot look up patients by name. Search must not become a way around the page
permissions, so there are tests asserting each denial rather than only the
permissions.

Nothing the server returns is interpolated into markup. Results are built as DOM
nodes with text set through `textContent` and hrefs set as properties, so a
batch number containing a quote is a batch number. A test feeds it
`B"><img src=x>` and asserts the URL comes back clean.

Shortcuts: `g` then `d`, `p`, `q`, `s`, `b` or `r` for home, patients, queue,
stock, brief and reports. `?` shows the list.

### Dark mode

A rebuilt palette rather than an inversion, following the system preference
until somebody chooses otherwise, then remembered. The theme is applied before
first paint, so a dark-theme user does not get a white flash on every page.

This surfaced a real contrast bug: `.button.primary` was `#fff` on
`var(--teal-dark)`, and in the dark palette `--teal-dark` is a pale cyan — white
text on a near-white button. Buttons now carry their own tokens in both themes.

### Sorting, density, and remembering

Any long table sorts by clicking a column, keyboard-reachable and reporting
`aria-sort`. Money and dates sort by value, not by their formatted text. A
compact-row toggle roughly halves row height for whoever works the long ledgers,
and both choices persist per person.

### Told before the work is lost

- **Connection.** The topbar dot turns red and a bar appears the moment the
  browser loses the network, so a ward on an unreliable link finds out before
  somebody finishes typing a payment into a form that cannot post.
- **Session.** Eight hours is long enough to start a clinical note and lose it.
  A warning appears before the session ends, with a way to keep it alive.
- **Confirmation on what cannot be undone.** Dispensing, approving a purchase
  order, verifying an M-PESA payment, reviewing a credit note, approving a stock
  count or a write-off — each now asks once, naming what will happen. Only those
  six; a confirmation on everything is a confirmation nobody reads.
- **Messages** announce themselves to a screen reader and can be dismissed.

## Accessibility and restraint

- Every behaviour is an enhancement. With JavaScript unavailable the pages still
  render, submit and navigate exactly as before — the tables simply scroll as
  they did.
- `prefers-reduced-motion` is honoured.
- Colour is never the only carrier: the wait bands, the offline state and the
  sort direction all have text or ARIA equivalents.
- Browser storage is wrapped in try/catch throughout; in a private window the
  preferences are simply not remembered.

---

## Verified

- **148 tests**, up from 133. The new ones cover search role-scoping (including
  the denials), URL safety, the wait bands, and money formatting round-tripping
  through a form.
- A scripted browser pass exercises the palette, both shortcut styles, sorting
  and its reversal, density, theme switching and persistence, offline detection,
  and phone layout on six pages — all passing, no console errors.
- `./scripts/checks.sh` exits 0.

Two of these were my own bugs, caught by that pass rather than by reading: the
palette pre-selected nothing so Enter did nothing, and closing it left focus in
the hidden search box, which then swallowed every keystroke including the
shortcuts.
